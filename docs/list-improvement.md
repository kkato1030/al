# al list 見やすさ改善

## 現状の挙動

- **フォーマット**: `Configured packages:` の下に、プロファイル名 → 各 provider で `  provider: pkg1, pkg2, pkg3, ...` を 1 行で出力。
- **グループ化**: プロファイル単位 → その中で provider 単位 → パッケージ名を名前でソートしてカンマ区切りで連結。

## 問題点

1. **1 行が非常に長い**: 1 provider に多数のパッケージがあると（例: core の brew で 20 個以上）、1 行が 200 文字超になり、ターミナルで折り返して読みづらい。
2. **スキャンしづらい**: カンマ区切りの長い行から特定パッケージを目で探しにくい。
3. **階層が弱い**: プロファイル名と「  provider:」が同じようなトーンで、ブロックの区切りが分かりにくい。

## 改善案

### 案 A: 折り返し（wrap）

- 現フォーマットを維持しつつ、「  provider: pkg1, pkg2, ...」を**ターミナル幅**（取得できない場合は 80）で折り返す。
- 折り返しはカンマ境界で行い、2 行目以降は空白でインデントして 1 行目のパッケージ列の開始位置に揃える。
- **メリット**: 変更が小さい。長い 1 行が解消され、どの端末でも読みやすい。
- **デメリット**: 依然としてカンマ区切りなので、スキャンしやすさの向上は限定的。

### 案 B: 1 パッケージ 1 行

- 各 provider の下でパッケージ名を 1 行 1 個で列挙。必要なら `brew (23):` のように件数表示。
- **メリット**: grep しやすい、目で追いやすい。
- **デメリット**: 縦に長くなり、全体を一覧するにはスクロールが増える。

### 案 C: 複数列（グリッド）

- 各 provider 内でパッケージ名を**固定幅の列**で並べる（例: 24 文字幅で 3〜4 列）。ターミナル幅に合わせて列数可変。
- **メリット**: コンパクトかつ整列して見やすく、スキャンしやすい。
- **デメリット**: 実装がやや複雑。名前長がばらつくと列によっては空白が目立つ。

## 推奨

- **まず案 A（折り返し）を採用**し、長い 1 行を解消する。
- 必要に応じて、後から案 C を `--columns` などのオプションで追加する余地を残す。

## 実装方針（案 A）

1. ターミナル幅を `golang.org/x/term` の `GetSize(0)` で取得。取得できないか 0 の場合は 80 を使用。
2. 行のプレフィックスは `  provider: `（例: 8 文字）。本文は `pkg1, pkg2, ...`。幅は `width - len(prefix)` で折り返し。
3. 折り返しは「, 」の境界でのみ行い、パッケージ名の途中で切らない。
4. 2 行目以降は、パッケージ列の開始位置に揃えるため、プレフィックス長と同じ数のスペースを付けてから続きを出力。
